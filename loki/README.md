# Loki plugin

The Loki plugin exposes read-only operations and datasources for registered Loki endpoints.

## Operations

- `loki.test` checks `/ready` for a registered endpoint.
- `loki.query` runs a bounded `query_range` LogQL stream query.
- `loki.recent_logs` builds a safe stream selector from common labels and an optional line substring filter.
- `loki.labels` lists label names or values.

All operations require `endpoint_ref`, which must refer to a registered Loki endpoint. Optional tenant auth is read from the `tenant_id` secret purpose and sent as `X-Scope-OrgID` through the host HTTP capability.

## Datasources

- `loki.log_entries` returns `loki.log_entry` records from live Loki queries.
- `loki.labels` returns `loki.label` records for label names or values.

Both datasources declare network access and the optional `tenant_id` secret purpose so host-backed datasource execution can perform the same HTTP requests as operations.

## Query limits and safety

- `limit` defaults to `100` and is capped at `1000`.
- `direction` is limited to `backward` or `forward`; default is `backward`.
- Label names are validated before calling Loki.
- Label values and line substring filters generated by `loki.recent_logs` are quoted with LogQL-compatible string escaping.
- The plugin only uses Loki read endpoints with HTTP `GET` requests.

## Examples

Run a bounded LogQL query:

```sh
dex op run loki.query '{"endpoint_ref":"staging-loki","query":"{job=~\".+\"}","since":"15m","limit":20}'
```

Search live log entries as a datasource:

```sh
dex datasource search loki.log_entries '{"endpoint_ref":"staging-loki","query":"{app=\"api\"}","since":"15m","limit":20}'
```

List label values:

```sh
dex op run loki.labels '{"endpoint_ref":"staging-loki","label":"app"}'
```
